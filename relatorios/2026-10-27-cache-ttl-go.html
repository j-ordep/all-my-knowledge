Do caso real ao conceito reutilizável.

Você extraiu um caso da empresa para um exemplo genérico. O próximo passo é conferir se o agente consegue preservar o comportamento ao levá-lo para outra codebase.

Para lembrar: o catálogo é uma ficha de consulta na mesa. O TTL indica quando conferir se ela mudou. A próxima chamada busca uma versão nova; se o banco falhar, pode continuar usando a anterior.

O que acontece no cache

Ele guarda definições de campos e fatores. As buscas dos dados finais continuam consultando o banco.

  1. 01 / CARREGAR

    Montar o catálogo

    Ler os metadados do banco e criar listas e mapas por chave.

  2. 02 / REUTILIZAR

    Dentro de 1 minuto

    Devolver o snapshot da última carga bem-sucedida.

  3. 03 / RENOVAR

    Na próxima chamada

    TTL vencido ou invalidação provoca uma tentativa de recarga.

  4. 04 / LIDAR COM FALHA

    Usar a versão anterior

    Se existir. Sem uma versão válida anterior, devolver erro.

Interpretação para a transferência

O contrato vale mais que o formato dos arquivos

Para orientar o agente, descreva quando recarregar e como responder a falhas e chamadas simultâneas. A organização do projeto pode mudar.

  • Dados antigos: o fallback não tem limite próprio de idade.
  • Concorrência: o mutex fica adquirido durante a carga; outros leitores do catálogo aguardam.
  • Compartilhamento: o snapshot precisa ser tratado como somente leitura. Cada processo mantém seu próprio cache.

Outro conceito do exemplo

Filtros guiados por metadados

O cliente descreve o filtro em JSON. O backend confere campo, tipo e operador no catálogo, escolhe expressões permitidas e passa valores separados do SQL.

Uma lista permitida controla nomes de coluna; parâmetros transportam os valores. São responsabilidades diferentes.

Confira se o conceito ficou claro

Passou um minuto sem requisições. O cache foi atualizado?

Não. O TTL vence, mas a recarga acontece quando uma chamada pede o catálogo. Não há uma rotina de atualização periódica no exemplo.

Invalidar é o mesmo que consultar o banco imediatamente?

Não. Invalidate zera o instante da carga. O próximo Get tenta recarregar e ainda pode usar o snapshot anterior se a consulta falhar.

O que falta para avaliar a aplicação na empresa?

O problema original, a alteração feita pelo agente e evidências do comportamento na codebase de destino. Um bom próximo passo é conferir primeira carga, TTL, invalidação, falhas e concorrência.
